公众号素材管理说明

公众号推送工作台属于后台最高管理员能力。草稿生成、媒体处理和同步结果都以接口返回的状态为准；HTTP 202、页面提示或单次请求成功不能单独证明微信草稿已创建。

一、入口与权限

浏览器入口是 /admin/mp-draft，对应静态源码 frontend/admin/mp-draft.html，运行文件由 npm run sync:frontend 生成到 public/admin/mp-draft.html。相关 API 挂载在 /api/mp，由 routes/mp-draft.js 负责，按接口要求登录并检查员工身份与具体权限；同步和人工核对要求 songs:review，任务状态还限制为本人可见。

公众号推送和校园广播点歌是两个流程：本页面负责生成公众号图文草稿，广播点歌仍由 /radio 和 /api/songs 处理。

二、工作流

  1. 打开后台公众号推送工作台，加载热点帖子、历史同日内容、每周之星和辅助信息。
  2. 选择帖子和可选栏目，调用生成接口，在页面核对标题、摘要、正文、图片、视频、点歌和二维码。
  3. 点击同步后，接口先返回 sync_id；页面持续查询数据库任务状态，直到草稿创建成功、带视频警告、草稿已创建但状态回写失败、需要人工核对或明确失败。任务由后台 worker 执行，进程重启后会按租约恢复可安全恢复的任务。
  4. 到微信公众平台草稿箱再次检查排版和素材，完成微信侧审核后手动发布。

图片会上传到微信素材地址；受控站内视频会按公众号素材限制处理，处理失败时正文保留封面和站内观看入口，并在状态中返回警告原因。不要因为视频警告或网络超时重复提交同一篇草稿。

needs_review 的处理：如果外部 draft/add 已开始但没有可靠的 media_id，任务会停在 needs_review。先到微信公众号草稿箱核对，再调用人工核对接口；系统不会因为未知结果自动重发，避免重复创建草稿。

三、环境变量

服务端从私有环境变量读取微信和素材配置：

WECHAT_APPID=公众号AppID
WECHAT_SECRET=公众号AppSecret
PUBLIC_WALL_ORIGIN=https://你的站点域名
WEATHER_API_KEY=可选的和风天气Key
WEATHER_CITY=上海
MP_DEFAULT_THUMB_MEDIA_ID=可选的默认封面media_id
FFMPEG_PATH=可选，默认ffmpeg
FFPROBE_PATH=可选，默认ffprobe

未设置默认封面 media id 时，服务会尝试使用站内封面资源；真实 Secret、Key、media_id 和部署凭据不能写入文档、源码或前端。

四、主要接口

接口用途
GET /api/mp/hot-posts加载热点帖子，hours 默认 24，limit 上限 50。
GET /api/mp/weekly-star加载指定周期的活跃用户。
GET /api/mp/today-history-posts加载历史上的同日帖子。
GET /api/mp/extra-info加载天气、一言和日期信息。
POST /api/mp/generate-content根据 postIds 和栏目选项生成可预览文章。
POST /api/mp/upload-cover上传封面并返回微信 media_id。
POST /api/mp/create-draft直接创建已准备好的草稿。
POST /api/mp/publish-daily生成并创建今日精选草稿；每日推歌仅最高管理员可带入。
POST /api/mp/sync-draft提交图片、视频和草稿同步任务，返回 sync_id。
GET /api/mp/sync-status?sync_id=...查询本人同步任务的进度和终态。
POST /api/mp/sync-review仅最高管理员、任务所有者且具备 songs:review 权限时使用。created 可处理 needs_review 或 mark_failed，必须带已核实的 media_id；not_created 仅处理 needs_review，必须带 confirm_no_draft: true。不会自动重发。
GET /api/mp/drafts / DELETE /api/mp/draft/:mediaId查询或删除微信草稿。

五、人工核对请求示例

只处理属于当前最高管理员的任务。needs_review 须先检查草稿箱；mark_failed 已有远端草稿，只允许补写本地状态，并沿用记录中的 media_id。确认微信草稿已经创建时：

POST /api/mp/sync-review
{
  "sync_id": "sync_...",
  "decision": "created",
  "media_id": "已从微信公众号草稿箱核对的 media_id"
}

确认草稿箱没有创建时，必须明确确认，服务只释放任务占用，不会再次调用微信：

POST /api/mp/sync-review
{
  "sync_id": "sync_...",
  "decision": "not_created",
  "confirm_no_draft": true
}

六、发布前检查

  • 检查标题、正文、图片替换、视频状态、文章来源链接和二维码在微信手机端是否可读。
  • 确认同步终态中的 media_id，再到微信草稿箱核对实际内容。
  • 页面改动后同步 frontend/ 与 public/，运行 npm run check:mirrors 及公众号相关回归脚本。
  • 公众号实际发布、微信接口投递和移动端展示需要在目标账号与目标设备上单独验证，静态检查不能替代这些验证。
